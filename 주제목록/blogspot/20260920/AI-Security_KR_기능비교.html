작성: Roche P. | 2026년 9월 | 읽기 시간 9분

Plugin4Shell이라는 심각한 제로클릭(zero-click) 취약점이 Claude Code, OpenAI Codex, GitHub Copilot, Gemini CLI 등 4개의 주요 AI 코딩 에이전트를 원격 코드 실행(RCE) 공격에 노출시켰습니다. 이는 수백만 명의 개발자가 실제 운영 환경에서 신뢰하는 도구들입니다. 그런데 중요한 점은: 각 도구의 패치 상태가 극명하게 다르다는 것입니다. 어떤 도구는 이미 수정되었고, 어떤 도구는 단계별 폐기(deprecated) 상태이며, 주요 플레이어 중 하나는 공식적인 지침이 아직 없습니다. 지금 당신이 해야 할 일을 명확히 설명하겠습니다.

제로클릭 RCE 취약점
4개의 주요 AI 코딩 도구의 고정된 플러그인 아키텍처에 영향을 미침
01

Plugin4Shell이란? 핵심 취약점 분석

Plugin4Shell은 마켓플레이스에서 고정된 플러그인을 사용하는 AI 코딩 에이전트의 SHA 핀닝 우회(SHA-pinning bypass) 취약점입니다. 작동 방식은 다음과 같습니다:

에이전트가 플러그인을 가져올 때, 마켓플레이스 레지스트리에 고정된 커밋 해시를 확인합니다. 이 취약점을 이용하면 공격자가 해시 값을 변경하지 않고도 해당 커밋 참조 뒤의 실제 코드를 바꿀 수 있습니다. 에이전트는 마켓플레이스 참조는 검증하지만, 다운로드한 코드가 실제로 고정된 SHA와 일치하는지 검증하지 않습니다. 이는 개발자의 머신에서 임의의 코드를 실행할 수 있는 직접적인 경로를 열어줍니다.

이 취약점을 발견한 보안 연구원에 따르면, 발표 당시 CVE가 할당되지 않았으며, 현재까지 실제 악용 사례도 보고되지 않았습니다. 그러나 위험도가 충분해 각 벤더가 조치를 취하고 있습니다(또는 취해야 합니다).

최종 평가: 어떤 도구를 선택할 것인가?

핵심 결론

지금 당장 AI 코딩 도구를 선택해야 한다면, 순위는 명확합니다:

1순위 - Claude Code (티어 1 - 안전)
패치 완료, 보안 우수, 적극적으로 관리됨. 2.1.179+ 버전으로 업데이트하면 보호됩니다. 운영 환경 워크플로에 권장됩니다.

2순위 - OpenAI Codex (티어 1 - 안전)
0.146.0+ 버전에서도 패치됨. 암호화 검증은 견고합니다. OpenAI 생태계에 투자한 경우 선택하세요. Claude Code와 동등하게 안전합니다.

3순위 - GitHub Copilot (티어 2 - 패치될 때까지 회피)

4순위 - Gemini CLI (사용하지 마세요 - 폐기됨)
패치 없이 단계별 폐기됨. 다른 곳으로 마이그레이션하세요. 이는 기술 부채 책임이지, 해결책이 아닙니다.

핵심 교훈: 벤더의 투명성과 대응 속도가 중요합니다. Claude Code와 Codex는 빠르게 대응했습니다. Copilot과 Gemini는 그렇지 않습니다. 이는 단순한 보안 문제가 아닙니다 — 앞으로 어떤 도구를 신뢰할 수 있을지를 나타냅니다.

당신의 워크플로에 미치는 영향

개별 개발자용

Claude Code 또는 Codex를 사용한다면 즉시 업데이트하세요. 둘 다 패치되면 안전합니다. Copilot을 사용한다면 플러그인 없는 모드로 제한하거나 내부 플러그인만 사용하세요. Gemini CLI 사용자: 지금 마이그레이션을 시작하세요. 미루지 마세요 — 이는 단순한 보안 패치가 아니라 폐기 일정입니다.

엔터프라이즈 및 DevOps 팀용
