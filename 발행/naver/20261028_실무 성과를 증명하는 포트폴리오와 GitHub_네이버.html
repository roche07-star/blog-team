"GitHub가 텅 비어서 떨어졌습니다" 면접장에서 눈물 흘렸던 민수님, 3개월 만에 달라진 비밀

안녕하세요, 헤드헌터 로체입니다 😊

오늘은 제가 담당했던 개발자 민수님(가명) 이야기를 꼭 해드리고 싶어요.

첫 상담 때, 민수님은 제 손을 꼭 잡으시더니 이렇게 말씀하셨어요.

"로체님, 저 또 떨어졌어요. 면접관이 제 GitHub를 보더니 고개를 저으시더라고요..."

그때 민수님 목소리가 떨리던 게 아직도 생생해요. 💔


실력은 있는데, 보여줄 게 없었던 개발자

민수님은 중소기업에서 3년간 백엔드 개발자로 일하셨어요.

회사 프로젝트는 열심히 했지만, 개인 GitHub는 거의 방치 상태였죠.

"회사 일하느라 바빴어요. 개인 프로젝트 할 시간이 어디 있어요?"

솔직히 저도 이해했어요. 실무가 바쁜데 퇴근 후에 또 코딩하기가 쉽지 않잖아요.

하지만 문제는 면접장이었어요. 📉

"실무에서 어떤 기술 스택을 사용하셨나요?"
"구체적으로 어떤 문제를 해결하셨죠?"
"코드로 보여주실 수 있나요?"

이런 질문들 앞에서 민수님은 말로만 설명할 수밖에 없었어요.

증명할 수 있는 게 아무것도 없었거든요.


포트폴리오는 '작품집'이 아니라 '실력 증명서'예요

저는 민수님께 이렇게 말씀드렸어요.

"민수님, 포트폴리오는 새로운 프로젝트를 만드는 게 아니에요.
지금까지 해온 일을 정리하고 문서화하는 거예요."

그리고 함께 민수님의 실무 경험을 하나씩 꺼내봤어요.

✅ API 응답 속도를 30% 개선한 경험
✅ 레거시 코드를 리팩토링한 과정
✅ 테스트 커버리지를 60%까지 올린 이야기

"이거 다 훌륭한 포트폴리오 소재잖아요!"

민수님 표정이 조금씩 밝아지기 시작했어요.


목표 기업 JD를 분석하니 보였던 것들

그때 제가 민수님께 추천했던 게 jobizic이었어요.

제가 최근에 발견한 서비스인데, 후보자분들 반응이 정말 좋더라고요! 😊

민수님이 지원하고 싶은 회사들의 JD를 jobizic에 넣어봤어요.

그랬더니 이런 게 보이더라고요:

"Java, Spring Boot, MySQL - 이건 민수님이 실무에서 쓰던 거잖아요!"
"REST API 설계 경험 - 민수님이 3년간 해온 일이에요!"
"성능 최적화 경험 우대 - 민수님 그거 하셨잖아요!"

문제는 이 모든 게 GitHub에는 없었다는 거였어요. 📁

jobizic의 포트폴리오 진단 기능으로 보니,
민수님 GitHub에는 기술 키워드가 거의 매칭이 안 됐어요.

"아... 제가 이런 걸 전혀 안 보여주고 있었네요."

민수님이 처음으로 문제를 정확히 보신 순간이었어요.


3개월간의 변신 프로젝트

민수님은 그날부터 달라지셨어요.

1. 실무 코드를 공개 가능한 형태로 재구성

회사 코드를 그대로 올릴 순 없으니,
핵심 로직만 추출해서 샘플 프로젝트로 만드셨어요.

"레거시 코드 리팩토링하면서 배운 것들"
"MySQL 쿼리 최적화 실전 경험담"

어렵게 생각하지 않고, 실무에서 겪은 문제와 해결 과정을 솔직하게 쓰셨어요.

3. GitHub README를 이력서처럼 정리

프로젝트마다 이런 구조로 문서화하셨어요:

💡 어떤 문제를 해결했는지
🛠️ 어떤 기술을 사용했는지
📈 어떤 성과가 있었는지

그리고 중간중간 jobizic으로 체크했어요.

"목표 기업 JD랑 제 포트폴리오가 얼마나 매칭되는지 확인하면서 보완했어요."


"이번엔 떨리지 않았어요"

3개월 후, 민수님께서 연락 주셨어요.

"로체님, 면접 봤어요. 근데 이번엔 달랐어요."

면접관이 민수님 GitHub를 보더니 이렇게 물었대요.

"이 성능 최적화 프로젝트, 실무에서 하신 거예요? 구체적으로 설명해주실 수 있나요?"

민수님은 자신 있게 설명하셨대요.

README에 정리해둔 before/after 데이터를 보여드리고,
