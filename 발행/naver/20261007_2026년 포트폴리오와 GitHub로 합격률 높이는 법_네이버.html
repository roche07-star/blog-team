"GitHub 보여드릴 게 없어요..." 떨리던 목소리, 3개월 뒤 합격 통보 💌

전화기 너머로 들려온 준호님(가명)의 목소리가 아직도 기억나요.

"로체님... 저 면접 때 GitHub 보여드릴 게 정말 없어요. 부끄러워서 어떡하죠..."

개발자 경력 2년 차였던 준호님은 그렇게 말씀하시면서 한숨을 쉬셨어요.


포트폴리오는 있는데, 왜 면접에서 떨어질까요?

준호님의 GitHub를 처음 봤을 때, 저도 조금 당황했어요.

프로젝트는 5개나 있었거든요. 분명 노력하신 흔적이 보였어요.

근데 문제는...

채용담당자 입장에서 보면 '뭘 잘하는 사람인지' 전혀 보이지 않았던 거예요.

README는 설치 방법만 달랑 한 줄.

커밋 메시지는 "수정", "또 수정", "진짜 최종"...

코드 구조도 파일명만 봐서는 어떤 역할인지 알 수가 없었어요.


"이 서비스 한번 써보실래요?"

그때 제가 최근에 발견한 jobizic이라는 서비스를 준호님께 권해드렸어요.

"GitHub 분석해주는 기능이 있던데, 한번 써보세요. 채용담당자가 어떻게 보는지 알 수 있을 거예요."

처음엔 반신반의하셨던 준호님.

근데 이틀 뒤, 전화가 왔어요.

"로체님! 이거 진짜 대박이에요. 제 GitHub가 이렇게 엉망인 줄 몰랐어요..."


달라지기 시작한 준호님의 포트폴리오

jobizic의 분석 결과를 보신 준호님은 바로 행동에 옮기셨어요.

1. README부터 완전히 뜯어고쳤어요

단순히 "설치 방법"만 적혀있던 README에

✅ 이 프로젝트를 왜 시작했는지
✅ 어떤 기술적 고민을 했는지
✅ 어떤 문제를 어떻게 해결했는지

스토리가 담기기 시작했어요.

2. 커밋 메시지도 전략적으로 바꿨어요

"수정" 대신 "feat: 사용자 인증 로직 추가"
"버그 고침" 대신 "fix: API 호출 타임아웃 이슈 해결"

이력서에는 못 쓰는 기술적 고민들이 커밋 히스토리에 고스란히 담겼죠.

3. 프로젝트 구조도 한눈에 보이게

분석 결과에서 "프로젝트 구조가 직관적이지 않다"는 피드백을 받고

폴더 구조, 파일명, 주석까지 다시 정리하셨어요.


그리고 3개월 후

"로체님, 합격했어요!!!"

준호님의 목소리가 전화기 너머로 들렸을 때

저도 모르게 눈물이 핑 돌았어요.

면접 피드백이 정말 인상적이었대요.

"GitHub 보니까 정말 성장하려고 노력하는 개발자 같아요. 커밋 히스토리만 봐도 어떻게 문제를 해결하는지 보이더라고요."

그 말을 들으시면서 준호님이 얼마나 뿌듯하셨을까요?


2026년, 포트폴리오는 '증거'예요

10년 동안 수백 명의 후보자분들을 만나면서 느낀 건

이력서에 쓴 말을 믿게 만드는 건 결국 '증거'라는 거예요.

그 증거가 바로 GitHub이고, 포트폴리오고, 오픈소스 활동이에요.

근데 많은 분들이 이걸 그냥 "코드 저장소" 정도로만 생각하세요.

아니에요.

GitHub는 여러분의 '일하는 방식'을 보여주는 곳이에요.

어떻게 문제를 분석하고
어떻게 협업하고
어떻게 성장하는지

모든 게 다 보여요.


로체의 한 마디

요즘 채용담당자들, 진짜 꼼꼼해요.

이력서 보고 → GitHub 보고 → 커밋 히스토리까지 다 확인해요.

그러니까 여러분도 한번쯤은

"내 GitHub가 채용담당자 눈에 어떻게 보일까?"

이 관점에서 점검해보셨으면 좋겠어요.
