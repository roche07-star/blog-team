✍️ 스타일: 네로 (네이버 블로그)

"면접관님, 제 GitHub 좀 봐주세요..." 떨리는 목소리로 말했던 민준님의 3개월 후

안녕하세요, 헤드헌터 로체입니다 😊

오늘은 제가 담당했던 신입 개발자 민준님의 이야기를 들려드릴게요.
첫 상담 때 민준님의 눈빛을 아직도 잊을 수가 없어요.

"로체님, 저 면접 때마다 포트폴리오 설명하다가 말문이 막혀요.
뭘 만들긴 했는데... 면접관님들이 고개를 갸우뚱하시는 게 느껴져요."

민준님의 포트폴리오, 뭐가 문제였을까요?

사실 민준님의 GitHub를 처음 봤을 때,
제 마음이 좀 아팠어요.

프로젝트는 4개나 있었거든요.
근데 하나같이 README가 2~3줄...
커밋 메시지도 "수정", "완료", "ㅇㅇ" 이런 식이었어요.

"이게 뭘 해결하려고 만든 건지 모르겠어요."
면접관들이 가장 많이 했던 말이라고 하더라고요 😢

포트폴리오, 양이 아니라 '스토리'예요

제가 민준님께 가장 먼저 물어봤어요.

"민준님, 이 프로젝트들 중에서
가장 애착 가는 게 뭐예요?"

"음... 여행 일정 관리 앱이요.
제가 실제로 여행 갈 때마다 불편해서 만들었거든요."

바로 이거였어요!
문제 인식 → 해결 과정 → 결과
이 스토리가 포트폴리오의 핵심이에요.

민준님이 포트폴리오를 바꾼 3가지 방법

1. 프로젝트 개수를 줄였어요 (4개 → 2개)

충격적이죠? 😮
근데 이게 정답이었어요.

대신 선택한 2개 프로젝트는
README를 정성껏 작성했어요.

- 왜 이 프로젝트를 시작했는지
- 어떤 기술적 고민이 있었는지
- 어떻게 해결했는지
- 만약 다시 한다면 뭘 개선할지

이 4가지만 명확히 써도
면접관들의 반응이 달라져요 ✨

2. 커밋 히스토리를 정리했어요

솔직히 이건 시간이 좀 걸렸어요.
그래도 민준님, 정말 열심히 하셨어요.

기존: "수정", "ㅇㅇ", "됨"
→ 개선: "feat: 사용자 인증 API 연동", "fix: 날짜 선택 시 오류 수정"

이렇게 바꾸니까
"이 친구, 협업 가능하겠는데?"
이런 인상을 주게 된 거죠 👍

3. 내가 부족한 게 뭔지 객관적으로 파악했어요

이게 사실 가장 중요한데요,
제가 최근에 발견한 jobizic이라는 서비스를 민준님께 추천해드렸어요.

AI가 민준님의 포트폴리오랑
지원하려는 공고를 비교해서
"이 부분이 부족해 보여요" 하고 짚어주더라고요.

민준님이 지원하려던 회사는
"RESTful API 설계 경험" 을 원했는데,
포트폴리오에는 그 부분이 잘 드러나지 않았던 거예요.

그래서 여행 일정 앱에
API 설계 문서를 추가하고,
왜 이렇게 설계했는지 근거를 담았어요 📝

3개월 후 민준님의 연락

"로체님!!! 최종 합격했어요!!!"

카톡 알림이 울렸을 때
저도 모르게 소리를 질렀어요 😭

민준님 말씀이,
면접관님이 포트폴리오 보시더니
"프로젝트가 많진 않지만, 깊이 있게 고민한 흔적이 보이네요"
이렇게 말씀하셨대요.

그리고 커밋 히스토리를 보시더니
"협업 문화에 잘 적응할 것 같아요" 라는 피드백까지!

로체의 꿀팁 정리

신입 개발자 포트폴리오, 이것만 기억하세요

✅ 프로젝트는 2~3개면 충분해요 (대신 깊이 있게!)
✅ README에 '왜'를 담으세요
✅ 커밋 메시지는 협업의 시작이에요
✅ 공고와 내 포트폴리오의 갭을 객관적으로 파악하세요

마지막 팁은 정말 중요한데요,
jobizic 같은 도구를 활용하면
내가 놓친 부분을 빠르게 찾을 수 있어요.

AI가 공고 분석하고
"이런 경험 추가하면 좋겠어요" 하고
맞춤 과제까지 제안해주거든요 💡

민준님도 이걸로 부족한 부분을 채워서
포트폴리오를 완성했답니다!

여러분도 할 수 있어요

민준님이 마지막에 하신 말씀이
아직도 기억에 남아요.

"로체님, 저 포트폴리오 10개 만들려고 했었어요.
근데 2개를 제대로 만드니까 오히려 더 좋더라고요."

맞아요.
양이 아니라 질이에요 ✨

그리고 가장 중요한 건,
내가 만든 것에 대한 애정과 고민이 담겨 있어야 해요.

그게 면접관들에게도 전달되거든요 😊

포트폴리오 정리 화이팅입니다! 💪
