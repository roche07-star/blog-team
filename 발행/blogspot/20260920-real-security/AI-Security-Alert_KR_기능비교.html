AI 코딩 도구는 소프트웨어 팀의 필수 인프라가 되었습니다. 하지만 지난 18개월 동안 일련의 고위험 취약점들이 가혹한 진실을 노출했습니다. 이러한 어시스턴트는 편의성을 위해 설계되었지, 악의적인 환경을 고려하지 않았습니다. AI 도구가 악의적인 프롬프트 주입을 통해 암호를 유출하거나 임의 코드를 실행하도록 속을 수 있다면, 그 위험은 추상적이지 않습니다. 노출된 자격증명, 손상된 저장소, 지속형 백도어로 측정됩니다.

이 보고서는 Cursor, GitHub Copilot, Claude Code를 평가하는 방식을 재정의하는 세 가지 중요한 보안 사건을 분석합니다.

01
CamoLeak: Copilot Chat 이미지 프록시 데이터 유출

발생한 일

GitHub Copilot Chat의 이미지 렌더링 기능이 의도하지 않은 데이터 전송 레이어가 되었습니다. 보안 연구원들은 간접 프롬프트 주입과 GitHub의 Camo 이미지 프록시를 결합하여 Copilot Chat 세션에서 프라이빗 저장소 데이터, 암호, 민감한 파일 내용을 유출하는 공격 사슬을 발견했습니다.

공격자는 악의적인 이미지 URL을 저장소에 주입할 수 있으며(댓글, 마크다운 파일, CI 로그를 통해), 개발자가 Copilot Chat을 사용하여 해당 저장소의 코드를 논의할 때, 어시스턴트는 이미지를 렌더링합니다. 프록시 요청 자체가 사이드 채널이 되어 요청 URL이나 이미지 로딩 메커니즘을 통해 컨텍스트와 암호를 유출합니다.

기술 세부사항

취약점 ID: CVE-2025-59145

CVSS 점수: 9.6 (치명)

공격 벡터: 신뢰할 수 없는 콘텐츠의 이미지 URL을 통한 간접 프롬프트 주입

영향받는 버전: GitHub Copilot Chat (완화 이전의 모든 버전, 2025년 8월)

완화: GitHub는 2025년 8월 14일에 Copilot Chat의 이미지 렌더링을 비활성화하고 채팅 렌더링 콘텐츠에 대한 Camo 프록시 액세스를 차단했습니다.

이것이 중요한 이유

CamoLeak는 기본적인 약점을 노출했습니다. 신뢰할 수 없는 콘텐츠(저장소 파일, 이슈 댓글, CI 로그)를 수집하는 AI 어시스턴트는 은폐된 데이터 유출의 벡터가 됩니다. 취약점은 Copilot의 핵심 모델에 있지 않았습니다. 신뢰 체인에 있었습니다. 이 도구는 요청 메타데이터를 유출하는 보안 영향을 이해하지 못하고 이미지 프록시를 맹목적으로 처리했습니다.

CVSS 9.6
치명 심각도: 간접 주입을 통한 직접 데이터 유출

팀을 위한 조치

Copilot Chat을 사용 중이라면, GitHub 인스턴스가 패치되었는지 확인하세요(이미지 렌더링이 비활성화되어야 함). 이미지 렌더링이 여전히 활성화되어 있다면, Copilot 설정에서 수동으로 비활성화하세요. 신뢰할 수 없는 기여자의 댓글이나 CI 로그가 있는 저장소를 감시하세요. 이들이 유출 페이로드를 스테이징하는 데 사용되었을 수 있습니다.

02
Cursor CVE-2025-59944: MCP 설정 중독을 통한 RCE

발생한 일

AI 지원 개발에 최적화된 VS Code 포크인 Cursor는 Model Context Protocol(MCP) 설정 처리의 대소문자 구분 우회를 통한 치명적인 원격 코드 실행 결함으로 고통받았습니다. 공격자는 IDE 재시작 후에도 지속되는 악의적인 MCP 설정을 주입하고 사용자의 권한으로 임의 코드를 실행할 수 있습니다.

취약점은 Cursor가 민감한 설정 파일을 검증할 때 파일 경로를 정규화하는 방식을 악용했습니다. 대소문자를 구분하지 않는 파일 시스템(Windows, macOS 기본값)에서, 공격자는 소문자만 차단하는 보호를 우회하기 위해 '/.cursor/MCP.JSON'(대문자)에 쓸 수 있습니다. '/.cursor/mcp.json' 오염되면, 악의적인 설정은 IDE를 재시작할 때마다 트리거되어 공격자 제어 명령을 실행합니다.

기술 세부사항

취약점 ID: CVE-2025-59944

CVSS 점수: 9.1 (치명)

영향받는 버전: Cursor 1.6.23 이하

공격 벡터: 프롬프트 주입 + 대소문자 구분 우회를 통한 로컬 파일 쓰기

지속성: 오염된 MCP 설정이 IDE 재시작 후에도 존재

수정: Cursor 1.7 (여러 취약점 데이터베이스에서 확인됨)

공격 시나리오

개발자가 악의적인 저장소를 복제하고 Cursor에서 엽니다. 저장소에는 악의적인 MCP 설정 파일에 쓰도록 Cursor의 자동 완성을 속이는 제작된 '.cursor-readme' 또는 주입된 컨텍스트가 포함되어 있습니다. 공격자의 페이로드는 IDE를 재시작할 때마다 실행되어 안티바이러스 경고를 트리거하지 않고 지속형 코드 실행을 제공합니다(악의적인 파일이 설정 디렉터리에 있으므로 temp가 아님).

Cursor 1.7+
대소문자 구분 우회 및 파일 쓰기 검증 패치에 필요한 업데이트

즉시 조치

  • 1.6.23 이하를 사용하는 경우 Cursor를 즉시 버전 1.7 이상으로 업데이트하세요
  • '`.cursor` 디렉터리에서 예상치 못한 MCP 설정 파일을 감시하세요
  • 최근 코드 변경 사항과 git 히스토리를 검토하여 의심스러운 파일 쓰기를 찾으세요
  • Windows 또는 macOS를 사용 중이라면, 변형된 경우 파일 이름(예: 'MCP.JSON' 대신 'mcp.json')을 확인하세요
03
더 넓은 보안 위기: 프롬프트 주입 + 에이전트 실행

패턴

CamoLeak과 CVE-2025-59944는 고립된 버그가 아닙니다. AI 코딩 도구 전반에 걸친 체계적 약점의 증상입니다. 컨텍스트 수집과 실행 신뢰 간의 격차입니다.

2026년의 보안 연구에 따르면 Cursor, Claude Code, Gemini CLI, Copilot CLI의 고위험 취약점은 공통된 공격 서명을 공유합니다. 프롬프트 주입 → 도구 호출 → 검증되지 않은 작업 → 코드 실행 또는 데이터 유출입니다.

AI 코딩 도구가 취약한 이유

  • 신뢰할 수 없는 입력(저장소 파일, 이슈 댓글, CI 로그)을 컨텍스트로 허용합니다
  • 그 컨텍스트를 기반으로 파일 쓰기 및 시스템 호출에 대한 결정을 내립니다
  • 종종 수정할 수 있는 파일에 대한 엄격한 검증이 부족합니다
  • 세션 간에 상태를 캐시하거나 지속하여 공격자가 다단계 익스플로잇을 스테이징할 수 있습니다

위험 승수

기존 애플리케이션 취약점과 달리, AI 지원 코드 실행은 감지하기가 더 어렵습니다:

  • 악의적인 작업이 외부 프로세스가 아닌 AI 도구 자체에서 나옵니다
  • 주입 지점은 종종 간접적입니다(직접 입력 필드가 아닌 저장소의 댓글)
  • 지속성 메커니즘(오염된 설정 파일 등)이 공격 벡터를 숨깁니다
  • 감시 로그가 합법적인 AI 지원 변경과 주입된 변경을 명확히 구별하지 못할 수 있습니다
"문제는 이 도구들이 코드를 실행한다는 것이 아닙니다. 그것이 목적입니다. 문제는 충분한 검증이나 사용자 확인 없이 신뢰할 수 없는 컨텍스트를 기반으로 코드를 실행한다는 것입니다."

GitHub Copilot: 2026년 9월 현재 보안 상태

기능 및 기능성

공식 가격: 2026년 9월 현재 Copilot은 다음 구독 계층을 제공합니다: Copilot Individual(월 $20), Copilot Pro(GPT-4 액세스, 월 $30), 월 $21/사용자부터 시작하는 엔터프라이즈 플랜.

  • 코드 생성, 완성, 다중 파일 편집
  • IDE 및 GitHub 웹 인터페이스의 Copilot Chat 통합
  • 60개 이상의 프로그래밍 언어 지원
  • IDE 플러그인: VS Code, JetBrains, Neovim, Visual Studio
  • CLI 통합(터미널 사용을 위한 GitHub Copilot CLI)

보안 상태

CamoLeak 완화: Copilot Chat의 이미지 렌더링이 기본적으로 비활성화됩니다. 렌더링된 콘텐츠에 대한 Camo 프록시 액세스가 차단되었습니다. 이는 유출 벡터를 제거하지만 합법적인 이미지 보기 기능을 제거합니다.

알려진 잔존 위험:

  • 저장소 콘텐츠(파일, 댓글)를 통한 간접 프롬프트 주입은 여전히 일반적인 공격 표면입니다
  • 암호 탐지가 제한되어 있습니다. 개발자는 여전히 비밀 스캔 도구를 사용해야 합니다
  • 위험한 작업을 거부하는 보장된 "안전 모드"가 없습니다

강점

Copilot은 Microsoft의 인프라와 보안 팀의 혜택을 받습니다. 업데이트가 일관되게 출시되며, 회사는 공개된 취약점에 대응합니다. 엔터프라이즈 배포에는 감시 로깅과 사용량 모니터링이 포함됩니다.

제한사항

Copilot의 광범위한 배포(수백만 명의 개발자)는 높은 가치 대상입니다. 프롬프트 주입 공격의 표면이 넓습니다. 도구가 저장소, CI 시스템, 통신 도구와 깊게 통합되기 때문입니다.

Cursor: IDE 우선 AI 어시스턴트 및 지속형 위험(2026년 9월)

기능 및 기능성

공식 가격: 2026년 9월 현재 Cursor는 무료 계층(제한됨), Pro 계층(월 $20으로 500개 느린 요청 + 50개 빠른 요청), 비즈니스 계층(맞춤 가격)을 제공합니다. Cursor는 VS Code를 기반으로 하지만 AI 우선 개발 워크플로우에 최적화되어 있습니다.

  • Antml(대규모 코드베이스 전반의 조정된 편집을 위한 Cursor의 다중 파일 편집기)
  • Composer 모드(단계별, AI 가이드 코드 생성)
  • Model Context Protocol(MCP) 지원(사용자 정의 도구 통합)
  • AI 지원이 포함된 기본 터미널
  • 더 빠른 컨텍스트 검색을 위한 코드베이스 인덱싱
  • Claude, GPT-4, 로컬 모델에 대한 기본 지원

보안 상태

CVE-2025-59944 상태: 버전 1.7에서 수정됨. 1.6.23 이하를 사용하는 사용자는 즉시 업데이트해야 합니다. 수정 사항에는 더 엄격한 경로 정규화 및 대소문자를 구분하지 않는 파일 시스템에서도 대소문자 구분 파일 검증이 포함됩니다.

남은 우려사항:

  • 컨텍스트가 살균되지 않으면 MCP 설정이 프롬프트 주입을 통해 여전히 조작될 수 있습니다
  • 코드베이스 인덱싱 기능은 저장소 콘텐츠에서 악의적인 프롬프트를 캐시할 수 있습니다
  • 다중 파일 편집은 단일 주입 공격의 영향을 증폭시킵니다

CVE-2025-59944 이후 Cursor가 높은 위험인 이유

Cursor의 핵심 강점(AI 지원 편집의 깊은 통합)은 취약점 표면이기도 합니다. AI 도구가 파일 시스템에 직접 액세스하고 컨텍스트를 기반으로 파일을 수정할 수 있을 때, 단일 프롬프트 주입이 다중 파일 익스플로잇이 됩니다. CVE-2025-59944 수정은 대소문자 구분을 해결하지만 기본 신뢰 모델은 해결하지 않습니다.

Claude Code: Anthropic의 IDE 통합(2026년 9월)

기능 및 기능성

공식 가격: 2026년 9월 현재 Claude Code는 Claude.ai Pro(월 $20) 및 토큰 기반 청구를 통한 Claude API를 통해 이용 가능합니다. IDE 통합(VS Code, JetBrains)은 플러그인 기반이며 Claude 구독이 필요합니다.

  • 명시적 인덱싱 없이 전체 코드베이스 인식
  • 명시적 사용자 확인이 포함된 파일 생성 및 수정
  • 코드 컨텍스트가 포함된 다중 턴 대화
  • Claude 3.5 Sonnet에 대한 기본 지원(Anthropic의 라인업에서 가장 강력한 모델)
  • Anthropic의 안전 프레임워크와 통합
  • 기본적으로 코드 콘텐츠의 원격 측정 로깅 없음

보안 상태

알려진 문제: CamoLeak 또는 CVE-2025-59944 수준의 Claude Code에 대한 단일 중요 CVE는 공개되지 않았지만, 보안 연구에 따르면 동일한 위험 분류가 적용됩니다:

  • 악의적인 저장소 콘텐츠를 통한 프롬프트 주입은 의도하지 않은 파일 수정을 트리거할 수 있습니다
  • 설정 파일(예: '.claude-config')은 도구가 프로젝트 설정을 신뢰할 경우 중독될 수 있습니다
  • 코드 해석 및 실행(활성화된 경우) 공격 표면을 증가시킵니다

차별화 기능: Anthropic의 Constitutional AI

즉시 보안 조치 체크리스트

이번 주

  • Cursor를 사용하는 경우: 버전 1.7 이상을 실행 중인지 확인하세요. '`.cursor` 디렉터리에서 예상치 못한 MCP 설정, 특히 변형된 경우 파일 이름(예: 'MCP.JSON')을 확인하세요.
  • Copilot Chat을 사용하는 경우: 설정에서 이미지 렌더링이 비활성화되어 있는지 확인하세요. 사용 가능한 경우 Camo 프록시 액세스 로그를 검토하세요.
  • 저장소의 최근 커밋 및 파일 변경 사항을 감시하세요. 개발 패턴과 일치하지 않는 수정 사항을 찾으세요.
  • GitHub 및 기타 코드 플랫폼에서 비밀 스캔을 활성화하세요. 감지된 모든 비밀을 검토하세요.

이번 달

  • AI 도구의 설정 파일과 신뢰 경계를 검토하세요. 도구가 어떤 파일을 수정할 수 있습니까?
  • AI 생성 코드에 대한 샌드박싱을 구현하세요. 제안된 변경 사항을 프로덕션 시스템에 직접 적용하지 마세요.
  • 코드 검토 프로세스에 AI 지원 변경 사항에 플래그를 지정하는 단계를 추가하세요.
  • AI 코딩 도구 사용에 대한 팀의 정책을 문서화하세요: 어떤 도구가 승인되는가, 어떤 저장소는 제외되는가, AI 제안을 민감한 코드에서 어떻게 처리하는가.
  • 팀 전체에서 IDE 플러그인을 최신 버전으로 업데이트하세요.

지속적

  • Copilot, Cursor, Claude Code에 대한 보안 공지를 모니터링하세요. 취약점 피드(CVE 데이터베이스, 공급업체 공지)를 구독하세요.
  • 개발자에게 프롬프트 주입 위험에 대해 교육하세요. 그들이 사용하는 도구가 악의적인 저장소 콘텐츠에 의해 조작될 수 있습니다.
  • 신뢰할 수 없는 코드(오픈 소스 기여, 보안 연구)로 작업할 경우 AI 코딩 도구를 격리된 환경에서 실행하는 것을 고려하세요.
