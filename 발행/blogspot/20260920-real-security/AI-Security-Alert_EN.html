CamoLeak, Cursor CVE-2025-59944, Claude Code RCE - AI Coding Tools Security Crisis

AI coding tools have become mission-critical infrastructure for software teams. But in the last 18 months, a series of high-severity vulnerabilities has exposed a painful truth: these assistants were designed for convenience, not adversarial environments. When an AI tool can be tricked into exfiltrating secrets or executing arbitrary code through malicious prompt injection, the stakes aren't abstract anymore—they're measured in breached credentials, compromised repositories, and persistent backdoors.

This report breaks down three critical security incidents reshaping how teams should evaluate Cursor, GitHub Copilot, and Claude Code.

01
CamoLeak: The Copilot Chat Image Proxy Exfiltration

What Happened

GitHub Copilot Chat's image-rendering feature became an unintended data transport layer. Security researchers discovered a chain attack using indirect prompt injection combined with GitHub's Camo image proxy to exfiltrate private repository data, secrets, and sensitive file contents from Copilot Chat sessions.

An attacker could inject a malicious image URL into a repository (via comments, markdown files, or CI logs), and when a developer used Copilot Chat to discuss code in that repository, the assistant would render the image. The proxy request itself became a side channel—leaking context and secrets in the request URL or through the image-loading mechanism.

Technical Details

Vulnerability ID: CVE-2025-59145

CVSS Score: 9.6 (Critical)

Attack Vector: Indirect prompt injection via image URLs in untrusted content

Affected Versions: GitHub Copilot Chat (all versions prior to mitigation, August 2025)

Mitigation: GitHub disabled image rendering in Copilot Chat on August 14, 2025, and blocked Camo proxy access for chat-rendered content.

Why This Matters

CamoLeak exposed a fundamental weakness: AI assistants that ingest untrusted content (repository files, issue comments, CI logs) become vectors for covert data exfiltration. The vulnerability wasn't in Copilot's core model—it was in the trust chain. The tool blindly processed image proxies without understanding the security implications of leaking request metadata.

CVSS 9.6
Critical Severity: Direct data exfiltration via indirect injection

For Your Team

If you're using Copilot Chat, verify that your GitHub instance is patched (image rendering should be disabled). If image rendering is still enabled, disable it manually in Copilot settings. Audit any repositories with comments or CI logs from untrusted contributors—those could have been used to stage exfiltration payloads.

02
Cursor CVE-2025-59944: Case-Sensitivity RCE via MCP Config Poisoning

What Happened

Cursor, a popular VS Code fork optimized for AI-assisted development, suffered a critical remote code execution flaw through a case-sensitivity bypass in its Model Context Protocol (MCP) configuration handling. Attackers could inject malicious MCP configurations that persisted across IDE restarts and executed arbitrary code with the user's privileges.

The vulnerability exploited how Cursor normalized file paths when validating sensitive configuration files. On case-insensitive filesystems (Windows, macOS by default), an attacker could write to `/.cursor/MCP.JSON` (uppercase) to bypass protections that only blocked lowercase `/.cursor/mcp.json`. Once poisoned, the malicious configuration would trigger on every IDE restart, executing attacker-controlled commands.

Technical Details

Vulnerability ID: CVE-2025-59944

CVSS Score: 9.1 (Critical)

Affected Versions: Cursor 1.6.23 and below

Attack Vector: Local file write via prompt injection + case-sensitivity bypass

Persistence: Poisoned MCP config survives IDE restarts

Fixed In: Cursor 1.7 (confirmed across multiple vulnerability databases)

Attack Scenario

A developer clones a malicious repository and opens it in Cursor. The repo contains a crafted `.cursor-readme` or injected context that tricks Cursor's auto-completion into writing a malicious MCP config file. The attacker's payload executes every time the IDE restarts, giving them persistent code execution without triggering antivirus alerts (the malicious file is in a config directory, not temp).

Cursor 1.7+
Required update to patch case-sensitivity bypass and file-write validation

Immediate Actions

  • Update Cursor to version 1.7 or later immediately if you're on 1.6.23 or below
  • Audit your `.cursor` directory for unexpected MCP configuration files
  • Review recent code changes and git history for suspicious file writes
  • If you're on Windows or macOS, check for variant case filenames (e.g., `MCP.JSON` instead of `mcp.json`)
03
The Broader Security Crisis: Prompt Injection + Agent Execution

The Pattern

CamoLeak and CVE-2025-59944 aren't isolated bugs. They're symptoms of a systemic weakness across AI coding tools: the gap between context ingestion and execution trust.

Security research from 2026 shows that high-severity vulnerabilities in Cursor, Claude Code, Gemini CLI, and Copilot CLI share a common attack signature: prompt injection → tool invocation → unvalidated action → code execution or data exfiltration.

Why AI Coding Tools Are Vulnerable

  • They accept untrusted input (repository files, issue comments, CI logs) as context
  • They make decisions about file writes and system calls based on that context
  • They often lack strict validation of what files they're allowed to modify
  • They cache or persist state across sessions, allowing attackers to stage multi-stage exploits

The Risk Multiplier

Unlike traditional application vulnerabilities, AI-assisted code execution is harder to detect because:

  • The malicious action comes from the AI tool itself, not an external process
  • The injection point is often indirect (a comment in a repo, not a direct input field)
  • Persistence mechanisms (like poisoned config files) hide the attack vector
  • Audit logs may not clearly distinguish between legitimate AI-assisted changes and injected ones
"The issue isn't that these tools execute code—that's their entire purpose. The issue is that they execute code based on untrusted context without sufficient validation or user confirmation."

GitHub Copilot: Current Security Posture (September 2026)

Features & Capabilities

Official Pricing: As of September 2026, Copilot offers subscription tiers: Copilot Individual ($20/month), Copilot Pro (GPT-4 access, $30/month), and enterprise plans starting at $21 per user/month.

  • Code generation, completion, and multi-file edits
  • Copilot Chat integration in IDE and GitHub web interface
  • Support for 60+ programming languages
  • IDE plugins: VS Code, JetBrains, Neovim, Visual Studio
  • CLI integration (GitHub Copilot CLI for terminal use)

Security Posture

CamoLeak Remediation: Image rendering in Copilot Chat is disabled by default. Camo proxy access for rendered content has been blocked. This eliminates the exfiltration vector but removes legitimate image-viewing functionality.

Known Remaining Risks:

  • Indirect prompt injection via repository content (files, comments) remains a general attack surface
  • Secrets detection is limited; developers should still use secret scanning tools
  • No guaranteed "safe mode" that refuses to suggest dangerous operations

Strengths

Copilot benefits from Microsoft's infrastructure and security team. Updates roll out consistently, and the company has been responsive to disclosed vulnerabilities. Enterprise deployment includes audit logging and usage monitoring.

Limitations

The breadth of Copilot's deployment (millions of developers) makes it a high-value target. The surface area for prompt injection attacks is large because the tool integrates deeply with repositories, CI systems, and communication tools.

Cursor: IDE-First AI Assistant with Persistent Risk (September 2026)

Features & Capabilities

Official Pricing: As of September 2026, Cursor offers free tier (limited), Pro tier ($20/month for 500 slow requests + 50 fast requests), and Business tier (custom pricing). Cursor is built on VS Code but optimized for AI-first development workflows.

  • Antml (Cursor's multi-file editor) for coordinated edits across large codebases
  • Composer mode for step-by-step, AI-guided code generation
  • Model Context Protocol (MCP) support for custom tool integrations
  • Built-in terminal with AI assistance
  • Codebase indexing for faster context retrieval
  • Native support for Claude, GPT-4, and local models

Security Posture

CVE-2025-59944 Status: Fixed in version 1.7. Users on 1.6.23 or below must update immediately. The fix includes stricter path normalization and case-sensitive file validation, even on case-insensitive filesystems.

Remaining Concerns:

  • MCP configurations can still be manipulated through prompt injection if context isn't sanitized
  • Codebase indexing feature may cache malicious prompts from repository content
  • Multi-file editing amplifies the impact of a single injection attack

Why Cursor Is High-Risk Post-CVE-2025-59944

Cursor's core strength—deeply integrated AI-assisted editing—is also its vulnerability surface. When the AI tool has direct access to your filesystem and can modify files based on context, a single prompt injection becomes a multi-file exploit. The CVE-2025-59944 fix addresses case-sensitivity, but doesn't solve the underlying trust model.

Claude Code: Anthropic's IDE Integration (September 2026)

Features & Capabilities

Official Pricing: As of September 2026, Claude Code is available through Claude.ai Pro ($20/month) and Claude API with token-based billing. IDE integrations (VS Code, JetBrains) are plugin-based and require a Claude subscription.

  • Full-codebase awareness without explicit indexing
  • File creation and modification with explicit user confirmation
  • Multi-turn conversations with code context
  • Native support for Claude 3.5 Sonnet (strongest model in Anthropic's lineup)
  • Integration with Anthropic's safety framework
  • No telemetry logging of code content by default

Security Posture

Known Issues: While no single critical CVE has been disclosed for Claude Code to the level of CamoLeak or CVE-2025-59944, security research indicates the same class of risks apply:

  • Prompt injection via malicious repository content could trigger unintended file modifications
  • Configuration files (e.g., `.claude-config`) could be poisoned if the tool trusts project settings
  • Code interpretation and execution (if enabled) increases attack surface

Distinguishing Feature: Anthropic's Constitutional AI

Anthropic uses Constitutional AI training, which theoretically makes Claude more resistant to prompt injection. However, this is not a guarantee—the tool still executes code based on LLM decisions, and those decisions can be manipulated.

08
Immediate Security Action Checklist

This Week

  • If using Cursor: Verify you're on version 1.7 or later. Check `.cursor` directory for unexpected MCP configs, especially variant-case filenames (e.g., `MCP.JSON`).
  • If using Copilot Chat: Confirm image rendering is disabled in settings. Review Camo proxy access logs if available.
  • Audit recent commits and file changes in your repositories. Look for modifications that don't match your development patterns.
  • Enable secret scanning in GitHub and other code platforms. Review any detected secrets.

This Month

  • Review your AI tool's configuration files and trust boundaries. What files is the tool allowed to modify?
  • Implement sandboxing for AI-generated code. Don't directly apply suggested changes to production systems.
  • Add a step in your code review process that flags AI-assisted changes for explicit security review.
  • Document your team's policy for using AI coding tools: which tools are approved, which repositories are off-limits, how to handle AI suggestions in sensitive code.
  • Update IDE plugins to the latest versions across your team.

Ongoing

  • Monitor security advisories for Copilot, Cursor, and Claude Code. Subscribe to vulnerability feeds (CVE databases, vendor advisories).
  • Educate developers on prompt injection risks. The tool they're using can be manipulated by malicious repository content.
  • Consider running AI coding tools in isolated environments if working with untrusted code (open-source contributions, security research).
09
Final Verdict: Which Tool for Which Scenario?

For Enterprise Security-First Teams

Recommendation: GitHub Copilot (Enterprise)

Why? Despite CamoLeak, Copilot offers the most mature enterprise governance, audit logging, and security team support. Microsoft's infrastructure and rapid patching reduce risk. The image-rendering mitigation is a trade-off you can live with.

For Developers Prioritizing Speed & Coding Velocity

Recommendation: Cursor 1.7+ (with caution)

Why? Cursor's Antml and Composer modes are unmatched for multi-file refactoring and complex generation tasks. But update immediately to 1.7, audit your configuration, and avoid using Cursor with untrusted repositories without review.

For Teams Wanting Safety + Quality

Recommendation: Claude Code

Why? Claude 3.5 Sonnet is production-grade, Constitutional AI provides added safety, and explicit confirmation required before file modifications. Slower, but a good trade-off for risk-averse teams. Use for code reviews, refactoring, and secure development workflows.

The Honest Bottom Line

None of these tools are truly "secure" in the adversarial sense. They're all vulnerable to prompt injection when processing untrusted content. The ranking above reflects which tools have the best mitigations, fastest patch cycles, and clearest security postures—not which are "safe to use without thinking."

Treat AI coding tools like you treat any powerful automated system: with healthy skepticism. Review the output. Understand the context it was generated from. Don't blindly apply suggestions to critical systems.

10
What Comes Next? 2026 and Beyond

The Industry Response

Security researchers and vendors are rapidly pivoting. Expect:

  • Sandboxing improvements: AI tools that refuse to write to sensitive config directories without explicit user approval
  • Context filtering: Smarter detection of prompt injection payloads in untrusted input
  • Audit trails: Every file modification gets logged with the context that prompted it
  • Behavioral analysis: Detecting when an AI tool's actions deviate from expected patterns

What You Should Demand From Your Tools

  • Explicit whitelist of files the tool can modify (not just blacklist)
  • Clear audit logs of all AI-driven changes and the context that prompted them
  • Option to require user confirmation for any file outside a designated "edit zone"
  • Regular penetration testing and third-party security audits
  • Rapid disclosure and patching (sub-48 hours for critical CVEs)
"The security crisis in AI coding tools is not a problem with AI itself—it's a problem with how these tools integrate into your development environment. Fix the integration, and you fix most of the risk."
